# Xsan : bonnes pratiques en matière d’intégrité des données

Ces suggestions de consignes pour le déploiement de Xsan permettent de garantir un accès cohérent aux données stockées sur des volumes Xsan.

## Déployer une solution de sauvegarde

Il existe plusieurs moyens de sauvegarder des données, notamment des solutions matérielles et logicielles. Le processus de sauvegarde peut être un simple glisser-déposer de fichiers essentiels sur un volume local ou réseau, ou une manipulation plus complexe comme l’utilisation d’une solution logicielle qui sauvegarde des données sur une solution matérielle, telle qu’une bandothèque ou une matrice de disques, selon une programmation spécifique. Pour plus d’informations sur les solutions de sauvegarde, veuillez contacter votre représentant commercial Apple.

## S’assurer que l’alimentation fonctionne en continu

Utilisez un bloc d’alimentation sans interruption (UPS) pour vous assurer que tous les composants SAN restent disponibles pendant les pannes de courant.

## Effectuer une configuration pour des performances optimales

La liste de conseils disponible séparément vous permettra d’obtenir des performances optimales.

## Vérifier les verrous du boîtier

Si vous utilisez Xserve dans le déploiement Xsan, vérifiez que les verrous du boîtier Xserve sont enclenchés. Cela permet de s’assurer que les lecteurs de démarrage ne sont pas éjectés lorsque vous relâchez leur poignée sur les modules de lecteurs Xserve. Pour obtenir des instructions sur l’enclenchement des verrous du boîtier sur votre Xserve, consultez le [manuel](http://www.apple.com/server/documentation) produit Xserve propre au modèle utilisé.

## Effectuer une sauvegarde du fichier de configuration

Chaque fois que vous modifiez les options de configuration de Xsan, en créant un volume ou en envoyant un client vers un MDC, sauvegardez /Library/Filesystems/Xsan/config sur un volume externe.

## Utiliser la dernière version du logiciel Xsan

Utilisez régulièrement la fonction Mise à jour logicielle pour vous assurer que la version la plus récente de Xsan est installée.

## Vérifier le programme interne du commutateur Fibre Channel

Assurez-vous que votre commutateur Fibre Channel exécute une version compatible du programme interne. Pour le programme interne de QLogic, veuillez consulter les versions testées par Apple.

## Démonter et arrêter les volumes Xsan avant de redémarrer les cibles

Avant d’éteindre ou de redémarrer des périphériques de stockage, démontez et arrêtez tous les volumes Xsan qui incluent des LUN correspondant aux matrices hébergées sur les cibles à redémarrer. Certaines modifications administratives entraîneront le redémarrage des périphériques de stockage. Les contrôleurs RAID Promise VTrack redémarreront une fois leur programme interne mis à jour. Le Xserve RAID redémarrera si l’un des réglages suivants est configuré :

Admin RAID > Create Array (Créer une matrice)

Admin RAID > Delete Array (Supprimer la matrice)

Admin RAID > Réglages > Système

Admin RAID > Réglages > Réseau

Admin RAID > Réglages > Fibre Channel

Admin RAID > Avancé > Slicing (Découpe)

Admin RAID > Avancé > LUN Masking (Masque de LUN)

Évitez également d’effectuer des modifications dans Admin RAID > Avancé > Expansion entraînant la suppression d’une matrice préexistante si celle-ci agit comme un LUN qui a été intégré au volume Xsan.
