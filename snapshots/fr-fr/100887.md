# OS X Server (Yosemite) : vous devez disposer de noms d’hôte pleinement résolubles avant d’activer un réseau SAN

Lorsque vous effectuez une mise à niveau ou une migration de votre contrôleur de métadonnées vers OS X Server (Yosemite), vous devez disposer de noms d’hôte pleinement résolubles avant d’activer un réseau SAN.

Sous Yosemite, les contrôleurs de métadonnées Xsan stockent les informations de configuration du réseau SAN dans un répertoire LDAP, protégé à l’aide du protocole TLS. Pour que la protection puisse être correctement mise en place, chaque contrôleur Xsan doit être doté d’un nom d’hôte pleinement résoluble. Vos serveurs DNS doivent disposer, pour chaque contrôleur, des enregistrements suivants :

- Un enregistrement Address (A) unique pour le nom d’hôte du contrôleur, permettant d’obtenir l’adresse IP principale correspondante ;

- Un enregistrement Pointer (PTR) unique pour l’adresse IP principale du contrôleur, permettant d’obtenir le nom d’hôte de ce dernier.

Ces enregistrements DNS doivent être résolubles sur tous les contrôleurs de métadonnées et les systèmes clients du réseau SAN. Il peut être nécessaire de vous adresser à votre administrateur réseau afin que cette opération soit effectuée correctement.

Configurez vos enregistrements DNS avant d’activer votre réseau SAN. Si les noms d’hôte ne sont pas correctement configurés avant l’activation d’Xsan sur un contrôleur, les problèmes suivants peuvent survenir :

- L’application Serveur affiche le message « Le nom d’hôte de cet ordinateur n’est pas valide. Le nom d’hôte n’est converti en aucune adresse configurée de cet ordinateur. Veuillez vous assurer que le nom d’hôte est correct » ;

- Le fichier system.log comporte la mention « Impossible de déterminer le nom d’hôte pour l’évaluation du certificat ».

## Informations supplémentaires

Sous les versions d’OS X Yosemite antérieures à la version 10.10.3, des enregistrements DNS étaient également requis par Xsan pour les adresses et les noms d’hôte d’un réseau de métadonnées privé. Cela était dû au fait que ce réseau pouvait être utilisé lors des mises à jour de la configuration. En revanche, sous OS X 10.10.3 et version ultérieure, les systèmes Xsan utilisent uniquement le réseau principal lors de telles mises à jour. Mettez les contrôleurs de métadonnées à jour vers OS X 10.10.3 avant d’activer votre réseau SAN.

Pour en savoir plus sur le service DNS et OS X Server, consultez [l’aide](https://help.apple.com/advancedserveradmin/mac/3.1/?lang=fr) d’ [OS X Server](https://www.apple.com/fr/support/osxserver/) .
