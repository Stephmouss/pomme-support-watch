# Lion Server : redémarrage manuel des notifications Push après un changement de certificat

Découvrez comment redémarrer manuellement les notifications Push après un changement de certificat.

Si vous utilisez les notifications Push et :

- que vous avez précédemment configuré le service iChat de Mac OS X Server version 10.6 pour utiliser le protocole SSL, puis effectué la mise à niveau vers Lion Server, ou

- que vous avez changé de certificat (par exemple, s’il est arrivé à expiration) dans Lion Server

… vous devrez peut-être modifier les réglages de certificat manuellement pour les notifications Push.

### Changer le certificat utilisé par le service de notifications Push

- Arrêtez tous les services qui utilisent les notifications Push (comme Mail si Push est activé, le serveur iCal, le serveur du carnet d’adresses, etc.).

- Assurez-vous que le serveur de notification est arrêté en lançant : sudo serveradmin stop notification

- Exécutez la commande suivante : sudo serveradmin settings notification:sslKeyFile="(chemin)" … où (chemin) est le chemin d’accès complet vers le certificat SSL souhaité (probablement /etc/certificates/ hostname.GUID .concat.pem).

- Le cas échéant, exécutez : sudo serveradmin settings notification:sslCAFile="(chemin)" … où (chemin) est le chemin d’accès complet à un fichier de chaîne SSL/fichier d’autorité de certification intermédiaire qui serait fourni par votre fournisseur de certificats SSL (probablement /etc/certificates/ hostname.GUID .chain.pem).

- Démarrez un service qui utilise les notifications Push pour vérifier que celles-ci fonctionnent bien.
